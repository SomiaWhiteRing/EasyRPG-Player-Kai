# SDW：敌人行动过多与防御动画异常

2026-11-06。对应 [讨论 28 第 12 楼](https://viprpg.org/discussions/28#post-12)。

SDW 在原版中也使用 ATB，但等待模式会在玩家选择指令时暂停蓄力。EasyRPG 将存档中省略的等待模式读成了主动模式，又给 Maniac 套用了普通英文版 RPG_RT 的低槽加速公式。这两项叠加，直接造成了选菜单期间敌人持续、加速行动。战斗内切换指令缺失使游戏自己的等待控制也无法纠正它。

本次已修改公共 C++ 实现，并交付 Windows 可执行文件。验证包括 SDW 数据、原版进程读数、旧版/修复版实战、临时消费者检查及相关既有回归；没有将其扩大为全游戏、Android 或 Web 的完整验收。

## 输入与可重复场景

- 游戏：`D:\漢化工具箱\SDW_Fix\GameFIle_汉化`，使用其 `RPG_RT.exe`、数据库和资源。
- 起点：原文件 `Save10.lsd`。它带有旧 Player 810 元数据，不把它误称为原版生成的存档。原版可以加载它，适合对照同一状态。
- 隔离副本：`build/sdw-atb-20261106/repro`。复制游戏数据文件，资源目录用只读消费的目录联接；将 Save10 的前台事件栈替换为进入敌群 2，写入副本的 Save01。
- 使用真实角色、敌人、战斗公共事件与回调；没有删除公共事件、改敏捷或用无事件的空数据库代替 SDW。
- 原始 Save10 与测试前复制品逐字节相等；原始数据库与隔离复制品逐字节相等。

隔离场景制作脚本、原版采样脚本、临时检查源码和原始日志保留于 `build/sdw-atb-20261106`。最初一个事件栈夹具将“命令字节数”误写为“命令条数”，导致原版反序列化错误；修正后才用于以下实战对照。该夹具错误没有写入原游戏。

## 具体原因与修复

### 1. 省略的 ATB 模式默认值不一致

SDW 的 Save10 未写 `SaveSystem/0x8C`。实际原版初始化将等待开关置 1，省略字段保留这一默认值；旧 liblcf 的成员默认值为 0，载入后变成主动模式。

原版当前游戏二进制：等待开关位于 `0x1402766B5`，初始化写入 1 的指令在 `0x14008851C`。原版进程加载同一存档后，实际读到 `01`。相关反编译证据：`ev_bd6d8d72077f6d3bf34cd26369db5d630286309913e77441f0e616efacab1199`。

修复：在 Maniac 的 LSD 读取入口、包括 codepage 引起的第二遍读取之前，设定默认值 1；显式字段仍覆盖默认值。新游戏也使用原版等待默认值。写出 `0x8C` 时保留显式 0，避免用户选择主动模式后再次载入变回等待。普通引擎的缺省读取仍为 0。

相关文件：`lib/liblcf/src/lsd_reader.cpp`、`generator/csv/fields.csv`、生成的 `lsd_savesystem.cpp`、`src/player.cpp`。依赖变更已同步进仓库的 liblcf 补丁。

### 2. 战斗内的 5003 被漏掉

SDW 的公共事件 250 调用 286。286 检查 W 键、等待状态和游戏开关，再执行 5003。原版在通用解释器分派该指令；旧 Player 只在地图解释器实现它，战斗公共事件使用的解释器会将它跳过。

原版 `0x140043D95` 为对上述等待开关执行 XOR 1。当前二进制分派证据：`ev_21691ab29138375b23a4acc71c780b7a1fd2aa219f26cecefac150c5c361cfa9`。

修复：将切换处理放入共享解释器，让地图、战斗和公共事件读写同一个模式。同时允许 Maniac 的等待状态查询，不再要求它被识别成普通英文版引擎；非英文配置已有独立消费者检查。SDW 本次 Windows 自动识别实际为英文引擎，后一个门槛并非本场景的直接原因。

### 3. 套用了另一套 ATB 加速公式

实际 Maniac 的基础增量为：

```text
300000 / (sum_agi * 100 / (agi + 1))
```

旧 Player 在英文引擎识别下，还乘以 `max(1, (275000 - gauge) / 55000)`；空槽时为 5。当前 SDW 原版的 `0x14000AF70` 没有这一倍率。证据：`ev_58837cb55c4469a7bf9d8d77f8b9e00834e47e64f54aaf8d0d17a4604c67ea74`。

修复：仅对非 Maniac 的普通英文引擎保留这套倍率。敏捷均为 10 的一敌一我消费者中，Maniac 增量为 1657，普通英文引擎仍为 8285；两者均实测通过。SDW 的 ATB 回调继续在基础增量之后执行。

### 4. 战斗解释器收栈额外推进了输入帧

旧 `Game_Interpreter_Battle::OnFinishStackFrame` 连续调用两次 `Input::Update()`。这会推进 EasyRPG 的按键持有时间并清掉首次触发，公共事件执行越频繁，确认操作越容易被吞掉。原版内部重新查询键盘与 EasyRPG 推进输入逻辑帧具有不同语义。

修复：删除这层额外输入更新，沿用 Player 每逻辑帧已有的输入更新。公共事件返回值、SELF 清理和父栈续行仍由原来的基类完成。

原有两个检查曾断言“调用输入两次”，本次将它们改为验证实际消费者责任：当前确认触发保留、结束栈正确退出、数值/字符串/开关返回值交付、SELF 清理，以及父栈继续存在。没有用保存/恢复按键数组的额外机制去维持错误的调用次数。

### 5. 防御动画在相同状态通知时重新开始

`Sprite_Actor::DoIdleAnimation` 对防御状态无条件调用 `SetAnimationState`。SDW 多名角色的防御姿势是完整战斗动画；每次状态检测都会销毁并重建动画、归零播放帧。即使防御状态未变，也会出现卡在起始帧或反复跳帧。

修复：已在防御循环时保留同一动画，只在姿势改变或动作结束需要回到待机时切换。临时消费者在原逻辑下连续得到 0，修复后得到 1、2、3、4、5；SDW 实战执行角色 8 的「ガード」后，记录到姿势 8 的帧 13、7、1、11、5、15 等持续循环，而非每次归零。

## 实战证据

| 条件 | 原版 RPG_RT | 修复前 Player | 修复后 Player |
|---|---|---|---|
| 同一起点载入的等待模式 | 1 | 0 | 1 |
| 停在指令菜单、不操作 | 两敌槽值持续保持 210040，行动 0 次 | 槽持续增长，日志中各敌行动计数增长至 7 次及以后 | 两敌槽值持续保持 209112，行动 0 次 |
| 按住 W | 模式变为 0、恢复蓄力 | 战斗内切换指令被跳过 | 模式变为 0、恢复蓄力 |
| 松开 W | 模式恢复为 1、槽值停止 | 不能由该战斗指令恢复 | 模式恢复为 1、槽值停止 |
| 新鲜起点的 W 蓄力速度 | 连续两个约 1 秒区间均增加 20160 | 额外低槽倍率 | 每 60 逻辑帧增加 20160 |
| 防御 | 实际选择并执行 | 相同状态检测会反复重建动画 | 实际选择并执行，动画持续推进 |

双方进场槽初值相差 928，本次未修改进场随机初始化，也不声称全战斗逐帧等价；暂停、恢复及同条件的增量已分别核对。原版先前施放过「翠華魔天」的另一轮记录速度不同，因此速率对照采用重新加载、未行动的新鲜场景。

主要记录：`native-fresh-wait.json`、`native-fresh-W-held.json`、`easy-before-trace.txt`、最终修复版日志及 `final-task-tests.txt`，均位于上述证据目录。

实机自动输入需要正确扫描码；字母键测试还切换到了英文输入状态。中文 IME 吞掉 SDL 字母事件时，原版直接查询虚拟键仍能看见按键，这属于宿主输入差异，本次依固定准则保留 EasyRPG 输入接口，未加入 Windows 专用轮询。

## 交付与验证记录

Windows Release Player 与测试程序通过构建，使用项目要求的 `builds/cmake/build-windows.ps1`、现有 ASCII 源目录联接和 `PLAYER_BUILD_LIBLCF=ON`。最终产品源码已移除全部临时采样代码。

通过的检查：

- 任务临时消费者：7 项、53 条断言，覆盖缺省读档、显式模式往返、战斗切换、菜单暂停、输入帧、线性增量、防御动画、非英文 Maniac 的等待查询。
- BattleAlgorithm：56 项、3290 条断言。
- 移除临时检查后的正式 Maniac 回归：90 项、1934 条断言，包含更新后的输入与类型化返回检查。
- 正式战斗解释器集合：4 项、111 条断言，属于上述集合的交叉复核，不重复累计。
- `git diff --check` 和 liblcf 补丁反向应用检查通过。

宽泛 Maniac 集合中的既有检查 `Maniac 250921 save resolves nonzero slot modes and invalid-slot results` 会在汇总前以退出码 0 结束整个进程。旧版、修复版均复现同一终止点，因此将它排除后运行其余 90 项；未把这项计为通过，也没有扩展修改无关存档语义。

可运行交付位于 `build/artifacts/sdw-atb-fix-20261106`：`Player.exe` 和 `Play-SDW.cmd`。启动器直接选择本机原游戏目录；也可将可执行文件复制至 RPG_RT.exe 同目录使用。存档和数据库无需手工修补。

最终无采样代码的可执行文件已在隔离 SDW 场景执行防御；启动器也已实际打开原游戏标题画面。启动器使用 Windows CRLF 换行，避免 cmd 对 UTF-8/LF 脚本的解析问题。

临时消费者已移出 `tests`，源码与可单独重放的检查程序保留在证据目录。最终交付包附报告与源码差异。

本报告记录本地 Windows 构建和验证；源码随 2026.11.2 版本提交。网页及 Android 的发布状态以对应构建/部署记录为准，原游戏文件未替换。
