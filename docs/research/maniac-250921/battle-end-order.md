## 本仓库的连接方式

1. `Game_Battle::CheckWin/CheckLose` 在状态或 DamagePop 回调执行期间暂缓判定。
   例如最后一个敌人死亡后，伤害回调先等待再复活敌人，等待期间不会锁定 Victory。
   不把参数、ATB、目标回调一律加入胜负门；原版证据只支持状态和伤害两个门。
2. 终止型 AsyncOp、窗口退出、重置和菜单永久移除 Battle 都取消当前战斗调用链。
   取消标志保持到战斗清理，效果消费者、吸血内部、多目标指令及 ATB / 目标写回停止后续副作用。
   已施加的效果保留，正常场景退场负责一次结果交付，不复制原版异常或内存布局。
3. 强制逃跑只在命令执行时有可行动或可恢复的非隐藏队员时接受。
   RPG2k3 已接受的强制逃跑保留阶段；新全灭结果成为 60 帧候选，下一次逻辑更新才开始消费。
   候选期间不调度新的战斗页，但继续执行逃跑状态机；长等待仍可让候选先到期。
   普通逃跑、阵形限制及已经成立的 Victory / Defeat 维持原有分支。
4. 同步回调遇到临时菜单，保持调用栈挂起，通过 `Scene::MainFunction` 推进菜单的
   Start / Continue / 异步续行 / 转场；返回 Battle 准备完成后继续同一个独立解释器。
   永久离开 Battle 则取消，不能把场景指针改变当作回调正常完成。

这些修改遵守 [固定行动准则](ACTION-GUIDELINES.md)：保留 EasyRPG 的输入、窗口、音视频、
场景和宿主等待机制，只适配结果、副作用、等待、取消及返回顺序。
