# im/pf 运行模式实现记录

日期：2026-10-14。范围依据为[运行模式报告](REPORT.md)，其文档及证据已先行提交为 `acb646cfe`。本文记录随后完成的源码接入与验证，不改写报告分析时的历史状态。

## 配置与生命周期

普通项目目录的 `RPG_RT.ini` 支持：

~~~ini
[RPG_RT]
pf=1
StepsPerFrame=0
~~~

|配置|采用的行为|
|---|---|
|缺省或 `pf=0`|im，缺省预算 10000|
|`pf` 的 32 位整数值非零|pf，缺省预算 200000|
|`StepsPerFrame` 的有符号 32 位值大于零|使用该预算，独立于模式|
|`StepsPerFrame` 缺项、零或负数|使用模式默认预算|
|既有配置或 `--no-patch` 禁用 Maniac|保留普通 EasyRPG 调度；pf 不隐式启用补丁|

读取保留 UINT 的 32 位位模式，再将预算解释为有符号整数，避免 Windows 的 `long` 解析提前溢出。十进制前导零不解释为八进制；支持 `0x` 前缀。有效上限由 `Game_ConfigGame::GetManiacExecutionLimit` 计算。

配置属于当前项目。`Player::CreateGameObjects` 重新建立项目配置，读 INI 前也恢复缺省值；新游戏、读档、战斗、SELF 切换不写这两个设置。没有增加版本档位、存档字段或 liblcf 字段。

版本查询仍通过 `ControlVariables::Other` 共享，返回 `250921 | (pf ? 0x80000000 : 0)`；表达式继续调用同一查询。战斗状态不再作为模式标志。

## 页刷新提交点

`Game_Map::RefreshAfterManiacChange` 承载原版受模式控制的提交：im 立即重选，pf 不执行这一次重选。整批范围写入完成后只调用一次，没有将刷新放进变量、开关的底层 setter。

|报告中的原版入口|Player 接入位置|
|---|---|
|024760，存档信息|`CommandManiacGetSaveInfo` 的完成出口，含失败结果；图片处理后结束|
|024bf0，鼠标位置|`CommandManiacGetMousePosition` 的结果写回尾部|
|024f10，保存结果|同步保存、无效槽结果及地图/战斗的异步保存结果提交|
|026a90，物品增减|`CommandChangeItems` 完成操作之后|
|026d70，队员变更|`CommandChangePartyMember` 完成操作之后|
|0282b0，按键输入|即时结果及等待输入结果提交；保留 EasyRPG 采样与接收|
|028c00 / 0293d0，扩展循环|已有循环输出提交点，含配对写入|
|02d1f0，计时器指令|`CommandTimerOperation` 完成操作之后|
|030e70，返回处理|既有返回值/开关交付点，在被调用者清理之前|
|0378d0 / 037de0，开关/变量|整个范围写入完成后|
|03de00，图片信息|几何信息结果写回尾部；像素和无效类型提前出口保留|
|03f620，数组|原有刷新尾部；没有给收集、逆序等提前返回统一增加刷新|
|040860，扩展输入|`CommandManiacKeyInputProcEx` 的结果提交|
|045660，等待输入 / SELF|等待结果提交及 SELF helper 完成出口|
|06ae10，自然计时|分别在计时器 1、2 的递减秒边界提交；先刷新，再执行各自的停止处理|
|0d3cd0，编辑/输入写回|EasyRPG 调试开关、变量编辑的结果提交；数字输入窗口使用相同提交策略|
|192ba0，pf 集中刷新|`Game_Map::Update` 的计时器、屏幕和图片更新之后，主解释器之前|

Maniac 下不再由解释器逐命令入口、解释器退出和地图更新开头任意消费脏标记。这样，原版没有刷新尾部的普通数据写入不会在 im 模式凭空触发重选，pf 的主事件写入也不会被下一条指令提前刷新。

pf 集中阶段复用现有 `MapUpdateAsyncContext`：恢复并行事件时走完剩余更新阶段；恢复前台事件时跳过已完成的计时器、图片及集中刷新。公共事件仍在轮到自己时读取启动开关，没有缓存到地图页刷新阶段。

移动路线开关的直接刷新、事件构造/装载时的页建立保留。补齐战斗返回、菜单开关效果及菜单转移提交的独立刷新；返回地图时仍消费 EasyRPG 场景产生的刷新请求。这些入口不套用 pf 提交抑制，也没有重写菜单、调试窗口或输入接收。

`AntiLagSwitch` 仍是单独的人为覆盖：pf 集中阶段遵守它；已有直接强制刷新和 im 的直接提交不经该脏标记查询。严格的一致性合同以未启用该覆盖为前提。

## 分派与执行预算

所有现有地图、并行、战斗及 Maniac 回调继续使用公共 `Game_Interpreter::Update`，其有效预算取自当前项目设置。

实现区分三种分派状态：正常返回、继续当前分派、结束本次执行。只有原版分派成功返回才增加预算计数。

- 报告列出的 36 条模式尾部路由，在 pf 下继续取指；im 下正常返回。阻塞返回仍停止执行。
- `3019` 生成指令重新进入同一分派入口，由生成后的实际路由决定是否返回，不给外层指令固定成本。
- 未知记录及原版内部跳过的标记不消耗外层预算。13 条已知直接跳过路由取自留存路由表，包含文字续行、条件结束等记录。
- `3022` 保留原版直接路由的空操作与模式尾部；其他预留的正常返回路由仍消耗一次预算。
- 只有重新进入原版分派入口时才处理等待前置条件；共享尾部继续取指不重复执行等待前置段。
- `Update(false)` 保留本次上限与余额，适用于子事件、连续前台事件和已有异步恢复。其他解释器及新一次真正更新拥有各自预算。
- EasyRPG 资源加载的 `YieldRepeat` 暂停当前分派，不提前消耗预算；重试游标在退出时回退，即使暂停恰好出现在预算边界也能重试。

实现时复核了 END 的返回成本：留存 `045660:1804–1819` 明确显示，END 在弹出被调用栈帧或重置/结束基帧之后返回成功，应占用一次外层预算。旧代码将 END 与内部跳过标记一起忽略，现已更正；liblcf 省略序列化 END 时，向量末尾使用等价完成路径。未借此重新审计其他指令的计算、绘制或战斗语义。

等待与异步位置是执行器的临时状态，没有新增存档模式或持久预算字段。没有增加墙钟限制，也没有按源码记录条数截断有限的 pf 共享尾部序列。
