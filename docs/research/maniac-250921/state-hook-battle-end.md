# 死亡状态回调与战斗收尾

2026-10-17。修复 Save10 对应武士奥普斯战后卡死所暴露的同步状态回调问题。

## 原版依据

固定对照：Maniac 250921 English RPG_RT.exe，SHA-256
`082df5cf00fd3c7647db52d400b53bb9db2350dd71d672709f59bc537a67fb3f`。
复用已有 REA/Ghidra 证据，并核对对应汇编；没有重新运行原版游戏。

- `0x140191250`：状态回调执行前将 `0x140279139` 置 1，调用
  `0x140187ee0`，返回后清零。同一标志也阻止状态回调自身重入。
  伪代码证据：`ev_3bde1e40db9b7eebf89ef1e96952213ab01d8e714102f2b847c748def17d241c`。
- `0x14018c080`：胜负检查入口在上述标志非零时直接返回，暂不判定双方全灭。
  伪代码证据：`ev_ec08bacfdcc50a4388faafe6daf9ba5891b4a0b02018f03880415b0590b51641`。
- `0x140187ee0`：每轮直接调用 `0x1401880c0` 推进独立回调解释器，
  未结束时再更新输入、战斗及显示，直到回调正常完成或退出。
  伪代码证据：`ev_53e770f1d91b1afc4505dc1dbe90592fe1cd09b48f12e2e974c0da89851d94cf`。
- `0x1401880c0` 的独立解释器不采用 `0x14008a040` 普通战斗事件执行器的
  存活敌人检查。回调结束、标志清零后，`0x140188680` 的后续更新才可确认胜负。

## 旧实现与修复

旧实现首次更新状态回调后，依靠嵌套场景更新继续运行。通用解释器可能在敌人全灭时，
于命令位置递增之前中断回调；场景随后进入胜利阶段并停止事件更新。
同步循环仍等待事件栈清空，而动作及结算又等待同步回调返回，形成互锁。
内循环没有处理宿主窗口事件，持续停留时还会显示窗口未响应。

修复保留现有状态回调重入标志，将它同时用于暂缓胜利和失败判定。
Maniac 的全灭中断规则只用于主战斗解释器，独立解释器继续执行合法命令。
同步驱动直接推进状态、参数和伤害回调；场景仅负责消息、计时及异步操作，
避免重复更新回调。驱动通过 EasyRPG 的输入和 UI 接口处理窗口事件、焦点暂停、
关闭及重置，并保留 Web 宿主让出执行和既有场景退出传递。

## 验证

Windows Release 的 `EasyRPG_Player_exe` 与 `test_runner_player` 构建通过，
使用既有 ASCII 构建目录及 `builds/cmake/build-windows.ps1`。

- 任务内临时无窗口消费者：6 项、454 个断言通过。覆盖 PF 开关、执行预算
  1/10000、最后敌人和最后队员的死亡状态回调、嵌套公共事件及等待、
  独立参数/伤害回调、回调内复活、关闭请求、焦点暂停与重置、普通战斗页全灭中断。
  使用模拟输入、UI 和场景观察点检查返回及副作用；没有模拟完整战斗场景状态机。
  临时测试源码已移除，不加入永久测试集合。
- 既有 `BattleAlgorithm`：56 项、3290 个断言通过。
- 既有 `Game_Interpreter` 中名称包含 `battle` 的检查：3 项、26 个断言通过。
- 更广的解释器集合运行未产生完整汇总，不计为通过；以上相关集合有明确通过汇总。

实际 Save10 完整战斗、返回地图剧情和窗口交互尚未实机验收。
