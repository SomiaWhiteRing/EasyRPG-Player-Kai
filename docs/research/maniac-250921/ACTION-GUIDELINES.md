# Maniac 兼容固定行动准则

2026-10-15，由用户确认。适用于本仓库后续 Maniac 筛选、迁移、修复和工作量评估；优先于旧的全量移植计划及其完成门槛。

## 目标

让 EasyRPG 正确执行 Maniac 游戏逻辑：结果、副作用、对象身份、等待和续行正确，资源能显示、更新、退出及恢复。不以“没有崩溃”“不支持指令直接忽略”代替功能实现。原版内部结构和宿主实现不作为复制目标。

数值求值、整数位模式、可观察的随机推进、图片状态与像素规则继续按已确认合同处理。字体发现、选择、字形生成和度量，以及输入、窗口、音视频、文件系统、平台持久化继续复用 EasyRPG。允许的字体差异不能掩盖解析、间距、颜色、透明度或生命周期错误。

## 固定取舍

1. 排除 ManiacVersion 配置与版本身份重建；使用现有 Maniac 检查及已接入的 im/pf 配置。不为复用旧代码重新引入选版系统。
2. 排除 GDI 字体趋同、原版窗口/控制台布局、线程和消息循环、Sleep/补帧/绘制资格及内部调用阶段的一一复刻。命令结果、逻辑帧、预算、等待、取消和写回仍需适配现有引擎。
3. 排除原版堆布局、无效指针、释放后读取、内存损坏和具体崩溃方式。合法短记录、SELF、存在性、别名、溢出和动态命令不能一并丢弃。
4. 全量版本/语言/平台等价、完整原版存档双向互通及 LSD 字节相等不作为本轮收尾门槛。Player 自存自读和恢复后继续执行属于相关功能责任。
5. 不预先穷举所有 CRT、数学库、正则引擎、异常阈值或命令组合。已有明确执行差异时，在最小相关范围内处理。
6. 每项迁移须说明具体行为差异、旧实现的依据、当前能力为何不足及连接位置。没有明确增益、与当前实现重复、会回退新修复或依赖整套原版驱动的候选不迁入。
7. 原版同步调用可以适配 EasyRPG 的异步/跨帧流程；保证参数捕获、效果次数、对象归属和返回顺序，不要求相同的函数、线程或状态机布局。不因未复刻原版 worker 而阻塞已有通用能力。
8. 按有限行为包交付，先列字段/模式/副作用和实际消费者，再迁移与检查。必要依赖纳入当前包；新的功能问题另行登记，不自动扩大工作包。

## 筛选与证据

旧分支按文件及行为分类为：迁移并适配、当前已有/当前更准确、排除原版复刻、保留证据而不迁代码。文件内的混合职责须注明具体提取部分；代码行数、编号数、断言数均不表示兼容率。

未知行为或尚未分开的产品/夹具问题不能作为可用代码的依据。保留其定位材料，不为消除未知而复制整个子系统。原版证据已有时复用，不重复固定身份或重跑全量逆向。

检查优先使用相关既有非 UI 集合和任务内临时消费者检查；永久新增测试、人工 UI/浏览器及子代理仍遵守用户授权约束。Windows 构建必须使用 `builds/cmake/build-windows.ps1` 和现有 ASCII 构建目录，配置与编译均在 ASCII 工作目录执行。

完成、静态依据、构建、消费者检查、实际游戏验收分别记录。连续两个检查点没有新增可观察证据时，留下具体未知项和恢复点，停止该未明问题的扩展；不能将这一暂停改写为功能完成。

## 本轮完成条件

Web 高负载问题同时遵守 [Web 高负载修复流程](../../web-performance.md)，区分采样、关闭采样器后的计时、消费者检查与实际游戏验收。

固定旧分支候选清单完成分类；所有判定可用的选定差异迁入并接通消费者，相关检查通过；排除及未知项具名保留。之后按新目标评估剩余行为包，不沿用“35/38”“168 入口全部闭合”或历史 40–100 人日作为完成条件。
