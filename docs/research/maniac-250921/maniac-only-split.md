# Maniac 独立分支拆分记录

本分支从拆分前的 `my-feature-stable`（`f28c77ac7`）建立。旧的上游提交 `78328fa29` 只用于辨认后来追加的行为，不是本次分支的基线。

## 已拆除的功能

拼音、交互高亮、小字、消息历史、视频播放、附带 SoundFont、站点导入器和归档站 Web 宿主等独立功能已从此分支移除。本次继续移除了独立的 `--detect-encoding` 命令和等待期间预解码大图片的优化；Maniac 游戏仍由普通图片加载路径同步读取图片。非 Maniac 游戏恢复原本的队员 ID 为零提示和事件位置模式处理，Maniac 游戏保留原来的相应兼容行为。

## 图片共享代码的取舍

- `Cache::LoadBitmap` 对 Maniac 的图片和图块设置 `Flag_ManiacPicture`；`Bitmap` 在颜色预乘之前保存原始 RGBA，供 Maniac 图片渲染、像素读取和透明度相关操作使用。普通 PNG 加载器保留零透明度像素的 RGB，因此不依赖已删除的预加载器。
- `Bitmap::WritePNG` 的透明通道输出被 Maniac 的图片写出命令使用，予以保留。
- 大图片的分块复制和精灵帧视图是共享绘图基础设施：用于避开 Pixman 的大尺寸坐标限制，让使用超大素材的游戏仍能显示。它们并非提前加载优化，予以保留。

## 三端衔接和检查范围

- Windows：Maniac 的系统音量接口使用 `winmm`，CMake 现无论原生 MIDI 是否启用都链接该库。
- Android：使用当前 SDL3 的 `SDL.setContext(Activity)` 接口；本机 SDL3 3.4.8 AAR 的声明已作静态核对。触摸输入、普通字体和 Android 宿主仍由 EasyRPG 处理。
- Web：使用标准 EasyRPG SDL 宿主，并保留 Maniac 控制台、输入和存档接入。旧归档站的浏览器存档位于不同路径，不会自动迁入；需通过存档导出、导入处理已有的游戏存档。
- 三端共用的 `liblcf` 必须包含 Maniac 存档字段。默认从已兼容的本地源码构建；本地源码缺少这些接口时，在构建目录获取固定版本并应用仓库中的补丁。现有本地工作副本及其修改不受影响。补丁已在临时干净源码上静态应用并核对所需接口。

2026-10-27：Windows Release Player 和现有测试运行器已构建。三个相关既有用例共 179 项断言通过；在 SDL 虚拟显示下，临时游戏使用原预加载器会命中的 2048×2048 调色板图集，透明像素的 Maniac 原始 RGB 为 `1193046`。该值在存档、读档后重新加载图片、再次读取并保存后仍保持不变。测试使用独立配置和存档目录，系统已有的视频设置未改变。

Web 构建现使用工具链提供的 SDL3 图形和音频后端。启动时发现 `post-js` 晚于 `preRun`，导致存档文件系统尚未选择即被挂载；游戏目录和 IDBFS 初始化现已移至 `preRun`。临时游戏在 Chrome 中确认了同一图集的透明像素、普通确认键、Maniac 扩展按键按下及释放、鼠标坐标；中文控制台输入经普通存档和 `Save.lgs` 写入后，重新加载仍一致。

上一轮对 `Invalid write` 日志的解释需要更正：普通 `Game_Variables::Set` 发出调试提示后仍会扩展全局变量，并非写入失败。它会裁剪数值，且不能写入负目标。原版 `0x140040860`、`0x140024bf0` 和 `0x14008c9e0` 的证据表明相关结果使用原始数值写入，负目标指向事件 SELF；扩展按键及鼠标命令现遵循这一行为。浏览器和 Android 的临时游戏分别确认未预分配的全局与 SELF 按键目标，以及分别写入全局和 SELF 的鼠标坐标。

Android ARM64 调试包已构建，并在独立 Android 12 模拟器的 ARM64 兼容层中运行。通过虚拟按钮进入测试游戏后，控制台输入、`Save.lgs`、普通存档和图片像素经应用重启读档后均保持一致；键盘按下及释放、模拟鼠标移动也已验证。此检查未覆盖实体 Android 设备。这些有限检查不代表所有 Maniac 游戏或全部行为均已验证。

## 2026-10-27 继续复查

- 存档信息、图片几何信息、媒体选项查询及保存结果仍有路径经过普通变量裁剪。存档信息的原版 `024760`、保存的 `024f10` 均调用原始赋值入口 `08c9e0`；现将这些结果写回接到现有的 `GetManiacWritable`，包括地图、战斗和钩子内的保存完成路径，不改变保存快照先于成功结果写回的顺序。临时游戏将普通变量范围设为 10～100：旧代码把成功结果 1 改为 10、图片宽度 1024 和日期改为 100；修复后保留原值，全局与 SELF 查询一致。
- 标准 Web 宿主恢复后仍残留退出时读取 `/tmp/message.png` 的回调，但当前 Player 已不生成该文件。旧构建的真实退出触发了文件错误，错误处理又因异常缺少 `message` 而出错。现删除这一失去生产者的回调，并让错误处理接受没有消息的异常。
- Web 触控键补齐取消时松键；滑出页面时不再对空命中结果读取 ID。任务内检查直接执行修改前后的绑定函数，复现并确认取消后松键和滑出页面的行为。SDL3 的取消触摸事件也释放跟踪槽，避免将中断的触摸留作持续按下或误判为点击。触摸位置字段目前没有消费者，未为其扩大改动。
- Windows SDL3 路径仍在调用 SDL2 的窗口句柄接口，现改用 SDL3 的窗口属性；实际链接又发现窗口代码的 `dwmapi` 依赖未显式声明，CMake 现予以补齐。Windows 默认 SDL2 的运行检查与可选 SDL3 的构建检查分别记录。
- 继续检查了已移除功能的构建引用、宿主入口和源码消费者，未发现拼音、消息历史、小字、推荐音源、追加视频后端或归档站专用宿主的运行入口残留。普通字体、用户自选 SoundFont、APK/ZIP 文件系统及平台输入属于原有宿主能力，继续保留。分支祖先仍为 `f28c77ac7`，没有换到新版上游。

本轮检查结果：Windows SDL2、SDL3 的 Release Player 和测试运行器均构建成功，同组 12 个既有用例、322 项断言分别通过；两个后端都在虚拟显示下完成限制变量范围的真实游戏运行、存档及读档。Chrome 和独立 Android 12 模拟器中的 ARM64 包也确认图片几何、存档日期、保存结果及原始透明像素不被裁剪，重载后保持一致；Android 存档文件另行读取核对。Web 退出不再触发旧回调错误，触控取消与错误处理的任务内检查通过。SDL3 原生取消事件的处理完成源码检查及平台编译，未单独进行设备上的取消事件注入验收。本轮未新增永久测试代码。

已知兼容范围仍有边界：`Maniac_KeyInputProcEx` 的操作 0/1 尚未区分手柄行为，手柄专用操作 3～5 仍走未支持分支；本轮没有已确认的跨平台参数映射及手柄设备证据，未据此补写猜测实现。实体 Android、浏览器系统指针定位和全量 Maniac 游戏行为也未获得本轮验证，不能将平台拆分检查表述为完整 Maniac 等价。
