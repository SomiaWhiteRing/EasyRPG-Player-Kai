# Work 250 网页高负载修复

2026-10-29 至 2026-10-30。目标是解决 `https://viprpg.org/play/250` 在敌人、弹幕与粒子增多时的持续掉帧；不继续用户已取消的原版 RPG_RT 动态对照。沿用本任务已有的构建、运行、实际游戏验证及提交发布授权。

## 对照身份与方法

生产对照为归档 285、运行时 `2026.10.7-site-8a6fbc7cf-br`，包括此前已发布的 pf 与镜头修复。使用同一份游戏资源、完整网页宿主和双 Worker，在 Chromium 151.0.7922.34 中回放真实战斗地图 Map0007，起点 (5,44)。

输入按逻辑帧固定：240 帧后持续 Z/X/鼠标左键，周期性 Space，并每 480 帧左右交替移动。任务内同时固定视觉随机种子和 Maniac 独立 LCG；生产包保留正常播种方式。压力回放只在测试钩子中将波次变量置为 9，使游戏走自己的第 9 波配置。该波有 100 个生成条目，并非 100 个敌人同时存在；配置含占位条目。生产游戏数据未修改。

正式计时关闭 CPU 采样器，并与编译、压缩串行执行。测量逻辑帧 600–3600；主循环成本排除复制变量快照的回调。实际 present FPS 使用提交次数与实际时间差计算，包含测试期间的全部画面提交。软件 WebGL 的提交自身平均仅约 0.09 ms，主要瓶颈在引擎 CPU 执行。额外的无调试器启动及硬件 D3D11 对照未推翻这一结论。

## 根因与修复

高频事件和表达式执行同时承受三类额外成本：JavaScript 异常处理的 `invoke_*` 包装、Asyncify 暂停／恢复插桩，以及 Binaryen 把单一调用者反复内联形成的巨大分派函数。每次逻辑更新超过 16.67 ms 后，已有补帧机制会在一次回调执行更多更新，进一步拉长画面之间的间隔。没有通过提高逻辑预算、少执行事件或减少对象来绕过负载。

- Web Player 和内置 liblcf 统一使用原生 Wasm 异常；libpng、FreeType 以相同 SDK 版本及 `SUPPORT_LONGJMP=wasm` 重建。两个库的公开配置宏与旧 SDK 一致。保留分配异常处理和 legacy Wasm EH 编码；链接中的 JS `invoke_*` 包装从 53 种降至零。
- 支持原生 Promise 集成的浏览器走 JSPI，其余浏览器走同源码的 Asyncify。异步导出 `web_main_loop` 完成后才调度下一帧，保持输入等待时的串行执行。宿主只选择一次变体，预取资源、游戏 Worker 和音频 Worker 使用相同选择；网站及 Android 适配覆盖两个入口。
- 限制 Binaryen 的单一调用者内联，使常见变量控制、数值条件与通用分派保持分离。快路径保留完整的地址解析、求值次序、溢出、截断、刷新及短记录补齐合同。
- 表达式使用字节快照与短记录栈缓冲，较大记录继续分配；保留输入别名写回的原语义。逻辑像素面按行读取原格式，拥有者视图仍通过逻辑像素接口读取。

没有采用 LTO、全局忽略间接调用或未经证明的 Asyncify 删除清单。

## 高负载实测

同一波次、种子和逐帧输入的配对结果：

|指标|生产对照|候选 JSPI|
|---|---:|---:|
|每次逻辑更新平均成本|20.83 ms|8.98 ms|
|整个主循环回调平均成本|213.80 ms|9.17 ms|
|主循环回调 P95|359.4 ms|13.9 ms|
|主循环回调 P99|390.7 ms|27.4 ms|
|实际画面提交 FPS|4.49|58.73|
|画面提交间隔 P95|373.3 ms|20.1 ms|

该结果支持本机此密集场景的持续掉帧已消除，不能解释成所有设备、所有波次都绝无长帧。候选仍有少量短尖峰；其 60 FPS 单帧预算内的 P95 与实际提交频率，比单看平均函数成本更有意义。

两版每 300 帧比较完整 `Game_Variables` 向量。12 个检查点各 300,001 个值，共 3,600,012 个值全部一致。这是游戏变量向量的等价证据，不是全引擎状态或全 Maniac 兼容率证明。对象类型槽的非零计数峰值为 52；此计数包含不同对象种类，不等于单独敌人数。

## 正确性与发布检查

- 按固定 Windows 包装入口、ASCII 构建目录及已打补丁的内置 liblcf 构建 Player 与既有 test_runner。
- 114 项相关既有用例逐进程执行，全部通过，共 2,433 条断言；逐项确认退出码、XML 闭合与实际用例计数，避免把此前整组运行在存档用例提前终止误报为通过。
- 任务内临时消费者比较通用路径和快路径，包括参数长度 0–9、槽零、间接目标、运算、条件跳转及表达式快照边界／输入别名，共 165,006 条断言通过。清除临时源码后的干净构建另通过 3 项直接相关既有用例、199 条断言。前一轮逻辑像素消费者覆盖 8 种格式、正负行距、视图和透明度，6,666 条断言通过。
- 实际 Wasm 调用控制台输入与文件输出确认，Promise 等待期间逻辑帧保持不变，随后按次序返回。C++ `length_error` 捕获及 libpng 的错误 longjmp 正常；JSPI 和 Asyncify 两种暂停机制均有直接消费者证据。

开启音频的同波次回放实测 57.96 FPS，主循环平均 9.92 ms、P95 16.0 ms；AudioContext 为 running，输出 RMS 0.204，确认有真实非零声音。JSPI 与 Asyncify 回退分别在 214 ms、200 ms 内完成停止保存。

不含测试钩子的干净 Web 包也已完成键盘／鼠标实际游玩、音频开启与停止；导出中无 `_work250`，未发生页面错误，停止保存耗时 279 ms。

临时钩子、固定种子与压力参数不会进入正式包。发布流程及同类问题检查要求已固定到 [Web 高负载修复流程](../../web-performance.md)。
