2026-10-15。本轮筛选与选定迁移已完成。固定准则见 [ACTION-GUIDELINES.md](ACTION-GUIDELINES.md)，源码迁移提交为 `c82ae475ac7acf1627de1b7c7a6913af034a3bdd`，文字自存自读补充为 `0a9886d6565711ac1193394cb27cb5518e8eb187`。目标是正确执行 Maniac 逻辑，保留 EasyRPG 的字体、输入和宿主实现；不以复制原版内部驱动作为收尾条件。

[逐文件筛选清单](legacy-screening-20261015.tsv)覆盖旧增量的全部 202 个 `src` 文件：27,616 行增加、1,037 行删除。它记录的是**迁移处置与职责边界**；不声称逐条命令、每个旧分支或每行源码均已验收。

## 2. 实际迁入的三个行为包

### P1：图片对象身份与换号

旧依据是 `game_pictures` 的 shared holder、`game_interpreter_maniac_pictures.cpp` 的 3017 合同和旧 `picture-implementation.md`。当前缺口是：槽位存储与 JS 保存的编号不能稳定表示同一个对象；换号后待完成的图片/文字请求也可能仍按旧编号挂接。

本轮改动：

- 图片、窗口槽位持有稳定对象；换号交换同一个对象。重叠范围按方向遍历，保留 32 位编号加法、逐对擦除和已产生的部分效果。
- 同步修正图片 ID、sprite ID/Z 和窗口槽位，保留对象的动画与像素状态。普通游戏继续懒分配，不迁旧构造器的整池初始化。
- 图片文件完成回调按请求绑定寻找实际对象；文字操作保存弱对象引用。请求完成期间换号仍挂到原对象。
- JS 图片引用跟随对象；池缩容后已失效引用不能访问新建的同号图片。同一非空文件名与已有位图保留快照，替换文件时取消旧文字操作而保留已有运动目标。

接入点为现有 3017、图片异步加载、文字 Operation 和 JS `Picture` 属性/方法。没有增加另一套 JS API 或复制原版指针失效行为。

### P2：原始/处理后像素的时机、布局与消费者

旧依据是 `Picture` 的 image/frame/stride/resource-sharing 字段、旧图片查询/输出入口与 `text-tile-implementation.md`；当前 [主报告 §7.10](REPORT.md)也已规定原始与处理后像素分离。当前缺口是：查询时生成 prepared bitmap 会改变观测时机，普通只读视图也会让“旧处理结果”随原始图编辑一起变化；sheet 与可变图还不能共用一种步长。

本轮改动：

- raw、prepared 和可读 processed 快照彼此独立。准备发生在正常更新/绘制及资源挂接，查询读取已有结果；完全透明和无效 frame 保留已有处理结果。
- 区分资源 sheet 的 frame 分配与可变图片的完整分配；分离图像宽高、frame 宽高、步长和资源共享标志。读取合法的线性像素地址，不把落在下一行的已分配像素误判成越界。
- 可变图复制保留 alpha=0 的 RGB。编辑/flatten 取消文字归属并转为 kind2；不重新 Show 或重新套色调。
- 将这些状态接到 3008 像素查询、3030 PNG 输出与 3028 图块写入。clear 同时清 raw/processed，tile 写入只改 raw；当前/同名 chipset 跳过零 alpha，另选 chipset 按原始像素复制。缓存将现有直通 RGBA 能力用于 Maniac chipset。
- 保留当前 autotile 规则和 `maniac_picture_renderer` 的色调、合成、缩放、旋转与波形实现；查询几何继续使用已确认舍入和除法顺序。

无效地址越出实际分配时返回透明像素或跳过写入；没有复制原版无效指针和堆破坏。此边界与合法的负坐标裁剪、短参数、重叠和银行寻址分别处理。

### P3：文字解析快照、资源等待、取消与自存自读

旧依据是 `maniac_text_cursor`、typed token、文字 Operation 和 3007 原始记录消费。当前 [主报告 §8](REPORT.md)的背景、图标、阴影和字形混合规则继续保留。当前缺口是：预展开后再作为普通文本扫描，会让插入字符串中的字面转义再次执行；跨帧资源等待缺少对象归属和取消合同，固定角操作数模式还可能污染存档资源 kind。

本轮改动：

- 正文按 UTF-16 游标消费，解析为字形/颜色/图标 token；插入内容中的转义不重新进入扫描器。两段配置使用当前存在性与编码规则，不复制旧的空串判断回退。
- 缺省参数按原记录读取。捕获文字、宽高、样式及续行参数；资源准备完成后才读 XY，再挂到同一图片对象。固定角求值的高位模式与存储的 kind1 分离。
- Operation 由解释器与窗口明确持有，等待沿用 `YieldRepeat`。覆盖、erase、转可变图以及解释器取消会解除旧请求；迟到回调不能重新挂图。
- 字体发现、选择、字形和度量沿用 EasyRPG。背景/frame 与 `RenderManiacTextGlyph` 沿用当前准确公式，排除旧 GDI 字族提取、31 单位截断和较弱的掩码合成。
- 保存保留原版 canonical 图片名称，同时在已有 Player 私有窗口字段中保存解析后的 token。Player 自存自读使用这一快照，避免 `$`、颜色/图标转义以及空配置在恢复时被二次解释；私有转义保留插入的控制字符和空白行，不让它们变成分隔符。没有修改 liblcf schema。
- 删除被替代的 `Game_Windows` 重复文字解析和状态；普通 EasyRPG 窗口继续使用原有流程。

只含原版 canonical、没有私有快照的存档继续走原版恢复解析。没有以 Player 私有字段的往返检查宣称完整原版存档双向互通。

## 3. 为什么没有迁更多旧代码

### 已有能力与回退风险

当前数值、随机状态、表达式、字符串存在性、GLOBAL/SELF 和 im/pf 已有较新的实现；旧拆分文件不是独立的新能力。旧图片 Move 的 relative、RGB gate 与零时长规则会覆盖 `dcdc3c3ca` 的准确修复，本轮明确保留该修复。

旧数组准备范围与当前 GLOBAL 物理容量存在差异。本轮尝试映射后，既有容量合同不符；该差异没有在选定图片/文字消费链中证明必要增益，因此已撤回，没有修改既有测试期望。数组结果、别名和 SELF 处理仍保留。需要研究容量的可观察接口时，应给它单独的有限合同。

### 排除实现复制与保留逻辑责任

旧 `game_maniac_battle_pump_services.*` 单独增加 3,937 行，主要在复制原版内部服务/阶段图。X 类全部 32 个文件的旧增量合计 6,090 行，已具名排除。线程、消息泵、补帧、绘制资格和 GDI 的结构一致性没有继续投入；命令产生的行动、等待、一次效果与返回仍是兼容责任。

同样，N 类中的 native load 阶段、Map/MoveRoute、Pack、SaveInfo、媒体、消息与战斗含混合职责。本轮没有把“不是整个 native port”误读成“这些合法指令可以无效果”。它们只是在当前三个包之外，或尚不足以判断可直接复用；发生明确需求时按状态与消费者提取，不自动整包迁入。

### 旧战斗链不能充当可靠底座

旧归档的 `closeout-feasibility-followup-20261014.md` 记录 851 项中 819 通过、27 失败、3 崩溃、2 超时；这是旧候选的历史结果，本轮未重跑该矩阵。其最后补充把 Item→Skill 的 SP 不变归为产品行为，确认物品只消耗一次、目标已重绑定，但效果 owner 的具体子根因仍未找到。G1 消息宿主、G3 首次等待与 G2 动画崩溃仍是未知。

因此不迁完整战斗驱动，也不把旧绿记录与当前绿记录拼成“35/38 已可靠，只补三项”。上述材料保留为未来行动效果/目标身份包的定位依据。未知项不能因减小目标而自动变成无关，也不能阻塞已确认独立的图片/文字包。

## 5. 迁移后的剩余工作量

下面是迁移完成时的初步估计。后续[具体范围与工作路径分析](next-bounded-scope-20261015.md)将 R1–R3 收敛为六条消费链、24项义务，定位五处静态差异，并更正了 R2 不能统一承诺“等待后续行/副作用一次”的表述；下一轮执行以该细化边界为准。

旧报告的 168 入口/12 包和 40–100 人日预算针对全范围系统性等价；它们不再作为当前行动门槛。本轮也没有从旧新增行数按比例折算工期。

在已经迁入的三个包之外，**下一批能够给出有限预算的核心工作约 5–12 人日，置信度低**。这是三包合计的工程预算，包含定向分析、适配和非 UI 检查，不是所有 Maniac 游戏的最终完工承诺。

|剩余包|需要解决或确认的结果|可复用部分|预算与结项条件|
|---|---|---|---|
|R1：参数、银行与接收者的消费者核对|短记录/存在性、GLOBAL/SELF、别名，以及调用/返回实际接收者不因统一 helper 改变顺序|当前上下文、银行、表达式与调用基础；旧语料提供分型线索|1–3 人日；只核对现有报告具名的读取/写入/接收族，修确认差异；容量怪异行为不无证据整包加入|
|R2：hook、等待与取消的有限适配|按 busy重试、普通事件暂停、消息hook局部停止和宿主资源等待分别保持求值、续行、提交及取消|现有解释器、im/pf、AsyncOp；P3 的捕获/对象归属已经提供一个完成实例|初步2–5人日；具体边界与更新预算见细化报告，限定普通事件与消息 hook，不迁 battle worker 或追完整 native phase 图|
|R3：自存自读与资源生命周期|新游戏/地图退出/载入后的 owner、资源和继续执行匹配 Player 保存状态|当前私有保存字段、P1 holder、P2 kind2、P3 token 快照；旧格式材料用于查字段|2–4 人日；核对上述正常生命周期，发现缺失状态时只补相关字段/恢复连接；不要求 native LSD 字节相等|

R1–R3 已有大量基础设施；工作重心是接入和交互边界，未假定要重写三个子系统。本轮检查已覆盖的图片/文字合同不再从零重做。这三个包分别结项，未明行为不能被三个工期相加“包办”。

另有两类工作不计入上述预算：

- **独立功能需求**：额外 MoveRoute/地图信息、Pack、SaveInfo、媒体或旧共享保存能力。N 类是候选导航，不是默认开发队列；先确认当前缺失的可观察功能，再为选定功能独立估价。
- **战斗行动效果与目标身份**：3009/3010/3037 的旧耦合链存在已确认现象和未知原因。可以将“行动包→目标选择→效果一次→返回”定义成有限包，保留 EasyRPG 战斗驱动；目前缺少可靠的差异分类，不能给该包可信的修复收尾总价。旧 819/851 不提供工期下界或只剩若干小修的依据。

因此，当下没有依据再称“还差整套 Maniac 移植”，也没有依据称“5–12 人日后所有游戏一定可用”。**本轮筛选与选定迁移已经完成；可预算的下一批是 R1–R3，其他需求及战斗未知分别登记。**

## 6. 防止再次无限展开

继续开发时，每包只保留一份字段/模式/副作用表和实际消费者清单，沿参数产生、对象归属、更新/效果、取消、恢复检查结果。共享能力与入口接通分开记账；已存在 helper 不算消费者通过。

期望从已有原版分支或独立的非对称状态推导。仅 exit0、终态相等、保存往返或大量断言均不足以说明检查完成；必须有完整汇总和实际触及的消费者。发生夹具问题时先分开夹具与产品，不修改产品去迎合未确认的旧期望。

发现新问题先判断是否为当前包的必要依赖。属于新功能或未知机制则具名保留，保持当前包可交付。连续两个检查点没有新增可观察证据时停在恢复点；不得为了将所有旧文件归为“已迁”而继续复制原版驱动。
